# 18. よくある質問・注意点

## Full版とTrial版で何が違いますか？

→ [17. 版（エディション）の違い](17-editions.md) に一覧表があります。

要点だけ言うと、**変換品質・組版機能はどちらの版でも同じ**です。Trial版は、出力されるページ数に上限があります。

## X3/X4への送信がうまくいきません

送信機能は現在**一方向送信のβ版**です。次の点にご注意ください。

- 送信先はプライベートIPの登録済み・承認済み端末に限定されますが、通信経路自体を暗号化するものではないため、**信頼できる自宅LANなどでのみ使用してください**
- 同名ファイルは既定で`_2`、`_3`のように自動的に別名保存されます
- 通信切断後のバイト単位再開、複数端末への一括送信などは未対応です

## EPUB分割で「200件」を超えたら壊れますか？

壊れません。「1巻当たりの最大spine項目数」の既定値200は、実機で確認された上限ではなく暫定値です。
端末側の実際の上限が分かっている場合は、値を調整してください。

## 変換中にアプリを強制終了してもいいですか？

**しないでください。** ページ数の多いEPUB/TXT/Markdownの変換や、大きなXTC/XTCHファイルの編集・保存は、
一時ファイルを使いながら処理しています。通常終了であれば一時データは自動的に片付きますが、
OSの強制終了や電源断を行うと、次回起動時まで古い一時データが残ることがあります。

## RAR・CBRを開くのに解凍ソフトは要りますか？

**Portable版では要りません。** RAR / CBR の展開用に 7-Zip（`_internal/tools/7zz.exe` と `7z.dll`、ライセンス表記つき）を
同梱しています。PATHの設定なども不要です。同梱の7-Zipが見つからない場合は、その旨の確認メッセージが出ます。

なお RAR / CBR は[フォルダ一括変換](12-folder-batch.md)の対象外です。1ファイルずつ開いて変換してください。

## 提供元が分からないZIP/CBZ/RARファイルを開いても大丈夫ですか？

画像件数・展開サイズ・圧縮率・寸法などに安全上限を設けており、極端なファイルは開けないようにしています。
ただし完全に安全を保証するものではありません。**提供元不明のアーカイブは、OSを最新の状態にしたうえで開いてください**。

## XTCH v2 や LZ4圧縮のファイルが端末で開けません

XTCH v2 と LZ4圧縮したファイルは、**Simple Reader OS（SROS）専用**です。純正ファームウェアやほかのビューアでは開けません。
SROS を使っていないときは、出力形式を従来の **XTCH**（または XTC）にし、LZ4圧縮をオフにしてください
（→ [2章](02-basic-settings.md#xtch-v2-について)、[21章](21-sros.md)）。

## SROS の Comic Reader でマンガが開けません

Comic Reader は、端末の画面のちょうど縦横2倍の解像度のファイルだけを開きます。
機種を **Xteink X4 Comic**（X4・X4 Pro、960×1600）か **Xteink X3 Comic**（X3、1056×1584）にして変換し直してください。
Custom で寸法を打ち込んだときは、1pxでも違うと開けません（→ [21章](21-sros.md#comic-reader-用の機種)）。

## 禁則欠け補正を有効にしても何も変わりません

「禁則欠け補正」は現在**縦書きのみ**に対応しています。組方向を「横書き」にしている場合、設定を
変更しても補正は行われません。また、対象は本文段落の行に限られ、見出し・箇条書き・引用・注記などは
対象外です。補正対象の行が1行もない場合は、変換ログに「禁則欠け補正：対象行なし」と表示されます。

## 登録作品の「XTC状態」が「要再変換」「未変換」のまま変わりません

v3.3 では、登録作品一覧の［完成版をStudioへ］［続きだけStudioへ］で渡したEPUBを**最後まで変換すると、自動で記録**され「最新」になります。
変わらないときは、次を確認してください（→ [11章](11-narou.md#変換済みの記録自動記録)）。

- 登録作品一覧からではなく、ファイルを直接開いて変換した → 一覧から渡し直して変換する
- 変換を途中で停止した → もう一度変換する
- メイン画面のログに「自動記録できませんでした」と出ている → 一覧で **［ここまで変換済みにする］** を押し、作ったXTC/XTCHを選ぶ

## 「続き」が「✓ 続きなし」なのに、サイトには新しい話が出ています

「続き」は、**手元のEPUBにあって、まだXTCにしていない話**の数です。サイトは見にいきません。
先に **［サイトから新着を取得］**（1作品だけなら［選択作品だけ取得］）でEPUBを新しくしてください。
取得が終わると「続き」が数え直されます（→ [11章](11-narou.md#最初に新着と続きは別のものです)）。

## ［続きだけStudioへ］が押せません

「続き」列に `+4話` のような続きが出ている作品だけで押せます。
「要完成版」「初回」「修正1話」（新しい話がなく修正だけ）の作品は、［完成版をStudioへ］で全話を作り直してください。
取得方式が「AozoraEpub3直接」のときや、取得・変換の実行中も押せません。
理由は一覧の下の「次の一手」の案内にも出ます（→ [11章](11-narou.md#続き列の表示)）。

## エディタで直した原稿がプレビューに出ません

ツールバーの **［読み直し］**（F5）を押してください。ファイルを選び直さずにプレビューを作り直します。
歯車メニューの「元ファイルの変更を知らせる」をオンにすると、元ファイルが新しくなったときに
上部でお知らせします。数秒おきに確認しているので、Studioを前面にしたまま保存しても出ます
（→ [1章](01-getting-started.md#元ファイルを直しながら確認する)）。

**お知らせが出ないとき**は、次を確認してください。

- 歯車メニューの「元ファイルの変更を知らせる」にチェックが入っているか（初期設定はオフです）
- 変換の実行中ではないか（実行中は出しません）
- プレビューを作った対象と、編集しているファイルが同じか（別のファイルを保存しても出ません）
- ［×］で閉じた変更ではないか（同じ内容の変更では再び出ません。もう一度保存し直すと出ます）
- それでも出ないときは、`logs` フォルダの最新のログを開き、「元ファイル確認: 通知なし（…）」の行を探してください。
  カッコの中に、出なかった理由が1行で残ります

## XTC/XTCHを開いている間、［読み直し］で元ファイルの変更が出ません

XTC/XTCHを表示している間の［読み直し］（F5）は、**そのXTC/XTCHファイルをディスクから読み直す**ものです。元のTXT・Markdown・PDFなどの編集内容は反映されません。元ファイルを直したときは、［ファイルを開く］で元ファイルを選び直してください（→ [1章](01-getting-started.md#xtcxtchを開いているとき)）。

## PDFで濃淡補正を動かすと「応答なし」になり、重くなります

値を変えるたびに、プレビューを作り直しているためです。スキャンPDFは1ページが大きく、範囲が広いほど時間がかかります。

- プレビューの範囲（開始〜終了）を、調整したいページだけに狭くすると、軽くなります
- 反映方式を「手動」にすると、値を変えても作り直さなくなります
- スライダーは、動かしている間は作り直さず、離したときに1回だけ作り直します

詳しくは [13章](13-image-correction.md#濃淡補正の調整が重いとき) をご覧ください。

## 青空文庫の注記が反映されないものがあります

罫囲み・小書き・訓点などに対応していますが、**字詰め**の指定はまだ反映されません。
対応している注記は [10章](10-aozora.md#対応している青空文庫の注記) にまとめています。
注記の対象文字列が本文と一致しないときは、変換ログに入力警告が記録されるので、そちらも確認してください。

## 英語UIはどこまで対応していますか？

メイン画面と歯車メニューを中心に対応しています。記事URL・XTCツール・書籍情報・端末転送・青空文庫・
EPUB分割などの独立ダイアログには、日本語のままの説明・通知が一部残っています。
なろう小説のEPUB作成ヘルパー画面は、現時点では日本語専用です。

## このマニュアルに載っていない画面があります

メイン画面・設定の4タブ・小説URLの画面・横長分割の設定は v3.3 で撮り直しています。
ダイアログ類（書籍情報・XTCツール・記事URL・青空文庫・EPUB分割・端末転送など）の写真は以前の版のままですが、
画面の作りは変わっていません。

次の画面は、今回のマニュアル作成では画像を用意できていません。

- OS標準のファイル選択ダイアログ（開く／保存）
- 「Web表示」モードで実際にChromiumが描画した結果そのもの（設定画面は[9章](09-article-url.md)で確認できます）

気になる点があれば、遠慮なく開発チームまでお知らせください。
